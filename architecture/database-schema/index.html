    Esquema de Base de Datos - ChessPlayerAnalyzer

    Audiencia: Desarrolladores, DBAs Última actualización: 2025-09-13 Estado: Completo

    Documentación completa del esquema de base de datos PostgreSQL utilizado por ChessPlayerAnalyzer para almacenar partidas, análisis y métricas.

    <¯ Objetivo

    El esquema está diseñado para: - Almacenar partidas PGN con metadatos y tiempos de movimiento - Análisis granular por movimiento y por partida - Métricas agregadas de jugadores con análisis longitudinal - Referencia estadística para calibración y benchmarks - Escalabilidad para millones de partidas y análisis

    =Ã Arquitectura del Esquema

    Niveles de Análisis

    Game (Partida)
     MoveAnalysis (Movimiento)  Evaluación Stockfish
     GameAnalysisDetailed (Métricas por partida)

Player (Jugador)
     PlayerAnalysisDetailed (Métricas agregadas)

ReferenceStats (Calibración por ELO)

    Tecnologías

    • ORM: SQLModel (Pydantic + SQLAlchemy)
    • Migraciones: Alembic
    • Base: PostgreSQL 15
    • Tipos avanzados: JSON columns, ENUMs, Foreign Keys con CASCADE

    =Ê Tablas Principales

    1. Game - Tabla de Partidas

    Almacena partidas individuales con metadatos de Chess.com.

    CREATE TABLE game (
    id SERIAL PRIMARY KEY,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    pgn TEXT NOT NULL,

    -- Metadatos de la partida
    white_username VARCHAR,
    black_username VARCHAR,
    white_elo INTEGER,
    black_elo INTEGER,
    eco_code VARCHAR,        -- Código ECO (ej: B90)
    opening_key VARCHAR,     -- Clave de apertura (ej: sicilian_najdorf)
    time_control VARCHAR,    -- Control de tiempo
    termination VARCHAR,     -- Forma de terminación

    -- Tiempos de movimiento (Chess.com)
    move_times JSON          -- Array de millisegundos por movimiento
);

CREATE INDEX idx_game_white_username ON game(white_username);
CREATE INDEX idx_game_black_username ON game(black_username);
CREATE INDEX idx_game_eco_code ON game(eco_code);

    Ejemplos de datos: 

    {
  "id": 12345,
  "pgn": "[Event \"Chess.com Game\"]\n[White \"hikaru\"]...",
  "white_username": "hikaru",
  "black_username": "opponent",
  "white_elo": 3200,
  "black_elo": 2850,
  "eco_code": "B90",
  "opening_key": "sicilian_najdorf",
  "time_control": "180+2",
  "move_times": [2500, 1200, 800, 1500, ...]
}

    2. MoveAnalysis - Análisis por Movimiento

    Evaluación detallada de cada movimiento por Stockfish.

    CREATE TABLE moveanalysis (
    id SERIAL PRIMARY KEY,
    game_id INTEGER NOT NULL REFERENCES game(id) ON DELETE CASCADE,

    move_number INTEGER NOT NULL,
    played VARCHAR NOT NULL,         -- Jugada realizada
    best VARCHAR NOT NULL,           -- Mejor jugada según Stockfish
    best_rank INTEGER NOT NULL,      -- Ranking (1=mejor, 2=segunda, etc.)
    cp_loss INTEGER NOT NULL,        -- Centipawns perdidos

    -- Evaluaciones extendidas
    eval_before INTEGER,             -- Evaluación antes del mov.
    eval_after INTEGER,              -- Evaluación después del mov.
    legal_moves_count INTEGER,       -- Movimientos legales disponibles
    time_spent REAL                  -- Tiempo usado en segundos
);

CREATE INDEX idx_moveanalysis_game_id ON moveanalysis(game_id);
CREATE INDEX idx_moveanalysis_move_number ON moveanalysis(game_id, move_number);

    3. GameAnalysisDetailed - Métricas por Partida

    Métricas avanzadas calculadas para cada partida analizada.

    CREATE TABLE game_analysis_detailed (
    game_id INTEGER PRIMARY KEY REFERENCES game(id) ON DELETE CASCADE,

    -- === QUALITY METRICS ===
    acpl REAL NOT NULL,                    -- Average Centipawn Loss
    wdl_loss REAL NOT NULL,               -- Win/Draw/Loss probability loss
    match_rate REAL NOT NULL,             -- % coincidencia con motor
    weighted_match_rate REAL NOT NULL,    -- Match rate ponderado
    ipr REAL NOT NULL,                    -- Intrinsic Performance Rating
    ipr_z_score REAL DEFAULT 0,          -- Z-score del IPR
    precision_burst_count INTEGER DEFAULT 0,

    -- === TIMING METRICS ===
    mean_move_time REAL NOT NULL,
    time_variance REAL NOT NULL,
    time_complexity_corr REAL,           -- Correlación tiempo-complejidad
    lag_spike_count INTEGER DEFAULT 0,
    uniformity_score REAL,              -- Uniformidad temporal (0-1)
    clutch_accuracy_diff REAL,          -- Precisión bajo presión

    -- === OPENING METRICS ===
    opening_entropy REAL DEFAULT 0,
    novelty_depth INTEGER,              -- Profundidad de novedad
    second_choice_rate REAL DEFAULT 0,  -- % segundas mejores jugadas
    opening_breadth INTEGER DEFAULT 0,

    -- === ENDGAME METRICS ===
    tb_match_rate REAL,                 -- % coincidencia tablebases
    dtz_deviation REAL,                 -- Desviación DTZ promedio
    conversion_efficiency INTEGER,       -- Movimientos para convertir

    -- === ANOMALY & SUSPICION ===
    anomaly_score REAL DEFAULT 0,
    suspicious_quality BOOLEAN DEFAULT FALSE,
    suspicious_timing BOOLEAN DEFAULT FALSE,
    suspicious_opening BOOLEAN DEFAULT FALSE,
    overall_suspicion_score REAL DEFAULT 0,

    analyzed_at TIMESTAMP DEFAULT NOW()
);

    4. Player - Tabla de Jugadores

    Estado y control de procesamiento de jugadores.

    CREATE TYPE player_status AS ENUM ('not_analyzed', 'pending', 'ready', 'error');

CREATE TABLE player (
    username VARCHAR PRIMARY KEY,

    -- Estado de proceso
    status player_status NOT NULL DEFAULT 'pending',
    progress INTEGER NOT NULL DEFAULT 0,  -- 0-100%
    total_games INTEGER DEFAULT 0,
    done_games INTEGER DEFAULT 0,
    done_tasks INTEGER DEFAULT 0,

    -- Control temporal
    requested_at TIMESTAMP,
    finished_at TIMESTAMP,

    -- Error handling
    error TEXT,
    last_task_id VARCHAR            -- ID de tarea Celery actual
);

    5. PlayerAnalysisDetailed - Métricas Agregadas

    Análisis completo y longitudinal de jugadores.

    CREATE TABLE player_analysis_detailed (
    username VARCHAR PRIMARY KEY REFERENCES player(username) ON DELETE CASCADE,

    -- === MÉTRICAS GLOBALES ===
    games_analyzed INTEGER NOT NULL,
    avg_acpl REAL NOT NULL,
    avg_wdl_loss REAL NOT NULL,
    robust_loss REAL DEFAULT 0,           -- Loss robusto (outliers removed)
    avg_match_rate REAL NOT NULL,
    avg_ipr REAL NOT NULL,
    std_acpl REAL,                        -- Desviación estándar ACPL
    std_match_rate REAL,

    -- === ANÁLISIS LONGITUDINAL ===
    roi_mean REAL,                        -- Return on Investment promedio
    roi_max REAL,                         -- ROI máximo
    roi_std REAL,                         -- Desviación ROI
    step_function_detected BOOLEAN DEFAULT FALSE,
    step_function_magnitude REAL,
    peer_delta_acpl REAL DEFAULT 0,      -- Diferencia vs peers
    peer_delta_match REAL DEFAULT 0,
    longest_streak INTEGER DEFAULT 0,     -- Racha más larga de precisión
    selectivity_score REAL DEFAULT 0,    -- Selectividad de aperturas

    -- === PATRONES (JSON) ===
    time_patterns JSON DEFAULT '{}',      -- Patrones temporales
    opening_patterns JSON DEFAULT '{}',   -- Patrones de apertura
    suspicious_games_ids JSON DEFAULT '[]', -- IDs de partidas sospechosas
    performance JSON DEFAULT '{}',        -- Métricas de rendimiento
    phase_quality JSON DEFAULT '{}',      -- Calidad por fase
    benchmark JSON DEFAULT '{}',          -- Benchmarks comparativos

    -- === EVALUACIÓN FINAL ===
    risk_score INTEGER DEFAULT 0,         -- Score 0-100
    risk_factors JSON DEFAULT '{}',       -- Factores de riesgo
    confidence_level INTEGER DEFAULT 0,   -- Nivel de confianza

    -- === TEMPORAL ===
    first_game_date TIMESTAMP,
    last_game_date TIMESTAMP,
    analyzed_at TIMESTAMP DEFAULT NOW(),

    -- === MÉTRICAS ADICIONALES (JSON) ===
    time_management JSON DEFAULT '{}',
    clutch_accuracy JSON DEFAULT '{}',
    tactical JSON DEFAULT '{}',
    endgame JSON DEFAULT '{}',
    time_complexity JSON DEFAULT '{}',
    segments JSON DEFAULT '[]',           -- Segmentos de análisis
    change_points JSON DEFAULT '[]',      -- Puntos de cambio detectados
    cluster_id INTEGER,                   -- ID de cluster ML
    cluster_distance REAL                 -- Distancia al centroide
);

    6. ReferenceStats - Estadísticas de Referencia

    Calibración por rangos de ELO para benchmarking.

    CREATE TABLE reference_stats (
    id SERIAL PRIMARY KEY,
    elo_range_min INTEGER NOT NULL,
    elo_range_max INTEGER NOT NULL,

    -- Estadísticas esperadas
    expected_acpl REAL NOT NULL,
    expected_match_rate REAL NOT NULL,
    expected_time_variance REAL NOT NULL,
    expected_opening_entropy REAL NOT NULL,

    -- Desviaciones estándar
    std_acpl REAL NOT NULL,
    std_match_rate REAL NOT NULL,
    std_time_variance REAL NOT NULL,
    std_opening_entropy REAL NOT NULL,

    -- Metadatos
    sample_size INTEGER NOT NULL,
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_reference_stats_elo ON reference_stats(elo_range_min, elo_range_max);

    = Relaciones y Constraints

    Foreign Keys con CASCADE

    -- MoveAnalysis  Game (1:N)
FOREIGN KEY (game_id) REFERENCES game(id) ON DELETE CASCADE

-- GameAnalysisDetailed  Game (1:1)
FOREIGN KEY (game_id) REFERENCES game(id) ON DELETE CASCADE

-- PlayerAnalysisDetailed  Player (1:1)
FOREIGN KEY (username) REFERENCES player(username) ON DELETE CASCADE

    Índices de Rendimiento

    -- Búsquedas por jugador
CREATE INDEX idx_game_white_username ON game(white_username);
CREATE INDEX idx_game_black_username ON game(black_username);

-- Análisis por partida
CREATE INDEX idx_moveanalysis_game_id ON moveanalysis(game_id);
CREATE INDEX idx_moveanalysis_move_number ON moveanalysis(game_id, move_number);

-- Calibración por ELO
CREATE INDEX idx_reference_stats_elo ON reference_stats(elo_range_min, elo_range_max);

-- Búsquedas temporales
CREATE INDEX idx_game_created_at ON game(created_at);
CREATE INDEX idx_player_requested_at ON player(requested_at);

    =È Estimaciones de Tamaño

    Volumen de Datos Típico

    • Game: ~1KB por partida
    • MoveAnalysis: ~100B × 40 movimientos = ~4KB por partida
    • GameAnalysisDetailed: ~2KB por partida
    • PlayerAnalysisDetailed: ~5KB por jugador
    • Total por partida: ~7KB

    Proyecciones

     10,000 partidas     70 MB
100,000 partidas    700 MB
  1,000,000 partidas  7 GB

    = Consideraciones de Seguridad

    Datos Sensibles

    • PGN completos pueden contener información personal
    • Usernames son identificadores públicos de Chess.com
    • Sin datos personales (emails, IPs, etc.)

    Backup y Recovery

    • Backup diario recomendado para tablas principales
    • Particionado por fecha para tablas grandes
    • Compresión de PGN en almacenamiento

    =Ê Queries Comunes

    Top jugadores por métricas

    SELECT username, avg_acpl, avg_match_rate, risk_score
FROM player_analysis_detailed
WHERE games_analyzed >= 50
ORDER BY avg_match_rate DESC, avg_acpl ASC
LIMIT 100;

    Partidas sospechosas

    SELECT g.id, g.white_username, g.black_username, gad.overall_suspicion_score
FROM game g
JOIN game_analysis_detailed gad ON g.id = gad.game_id
WHERE gad.overall_suspicion_score > 50
ORDER BY gad.overall_suspicion_score DESC;

    Análisis temporal

    SELECT DATE(created_at) as fecha, COUNT(*) as partidas
FROM game
WHERE created_at >= NOW() - INTERVAL '30 days'
GROUP BY DATE(created_at)
ORDER BY fecha;

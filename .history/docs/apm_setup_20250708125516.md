# Configuración de Application Performance Monitoring (APM)

Este documento describe cómo configurar el sistema de Application Performance Monitoring (APM) para Chess Analyzer usando Sentry.

## ¿Qué es APM?

El Application Performance Monitoring (APM) es un conjunto de herramientas y prácticas que permiten:

- **Rastreo de errores**: Captura automática de excepciones con contexto completo
- **Monitoreo de rendimiento**: Medición de tiempos de respuesta y cuellos de botella
- **Distributed tracing**: Seguimiento de transacciones a través de servicios (FastAPI y Celery)
- **Alertas proactivas**: Notificaciones cuando ocurren problemas
- **Análisis de tendencias**: Identificación de degradación del rendimiento a lo largo del tiempo

## Configuración de Sentry

### 1. Crear cuenta en Sentry

1. Ir a [https://sentry.io/](https://sentry.io/)
2. Registrarse para obtener una cuenta gratuita (suficiente para proyectos pequeños)
3. Crear un nuevo proyecto:
   - Seleccionar "Python" como plataforma
   - Nombrar el proyecto (ej: "chess-analyzer")
   - Copiar el DSN proporcionado

### 2. Variables de entorno

Agregar las siguientes variables de entorno a tu archivo `.env`:

```bash
# ====================================
# APPLICATION PERFORMANCE MONITORING (APM)
# ====================================
# Sentry DSN - Obtener de https://sentry.io/
SENTRY_DSN=https://your-key@sentry.io/your-project-id

# Entorno de la aplicación (development, staging, production)
SENTRY_ENVIRONMENT=development

# Versión de la aplicación
SENTRY_RELEASE=chess-analyzer@1.0.0

# Tasa de muestreo de trazas (0.0 a 1.0)
# 0.1 = 10% de las transacciones se rastrean
SENTRY_TRACES_SAMPLE_RATE=0.1

# Tasa de muestreo de perfiles (0.0 a 1.0)
# 0.1 = 10% de las transacciones tienen perfil de rendimiento
SENTRY_PROFILES_SAMPLE_RATE=0.1

# Habilitar/deshabilitar Sentry
SENTRY_ENABLED=true

# Habilitar trazado distribuido
SENTRY_ENABLE_TRACING=true

# Modo debug de Sentry (solo para desarrollo)
SENTRY_DEBUG=false

# Número máximo de breadcrumbs a mantener
SENTRY_MAX_BREADCRUMBS=100

# Adjuntar stacktrace a todos los eventos
SENTRY_ATTACH_STACKTRACE=true
```

### 3. Configuración para diferentes entornos

#### Desarrollo
```bash
SENTRY_ENVIRONMENT=development
SENTRY_TRACES_SAMPLE_RATE=1.0  # Capturar todo para debugging
SENTRY_PROFILES_SAMPLE_RATE=1.0
SENTRY_DEBUG=true
```

#### Staging
```bash
SENTRY_ENVIRONMENT=staging
SENTRY_TRACES_SAMPLE_RATE=0.5  # 50% de muestreo
SENTRY_PROFILES_SAMPLE_RATE=0.5
SENTRY_DEBUG=false
```

#### Producción
```bash
SENTRY_ENVIRONMENT=production
SENTRY_TRACES_SAMPLE_RATE=0.1  # 10% para reducir costos
SENTRY_PROFILES_SAMPLE_RATE=0.05  # 5% de perfiles
SENTRY_DEBUG=false
```

## Características implementadas

### 1. Rastreo de errores

- Captura automática de excepciones no manejadas
- Contexto completo del error (stack trace, variables locales, request data)
- Agrupación inteligente de errores similares
- Notificaciones por email/Slack cuando ocurren errores nuevos

### 2. Monitoreo de rendimiento

- Tiempo de respuesta de cada endpoint
- Identificación de endpoints lentos
- Análisis de queries de base de datos
- Detección de N+1 queries

### 3. Distributed Tracing

- Seguimiento de transacciones desde FastAPI hasta Celery
- Visualización del flujo completo de análisis
- Identificación de cuellos de botella entre servicios

### 4. Métricas personalizadas

El sistema captura automáticamente:

- **Requests HTTP**:
  - Método, ruta, status code
  - Tiempo de respuesta
  - Tamaño de respuesta
  - IP del cliente

- **Tareas Celery**:
  - Nombre de la tarea
  - Duración
  - Estado (success/failure)
  - Reintentos

- **Análisis de ajedrez**:
  - Tipo de análisis (partida/jugador)
  - Número de movimientos analizados
  - Tiempo de procesamiento
  - Errores específicos del dominio

### 5. Breadcrumbs

Registro automático de eventos para debugging:

- Inicio/fin de requests HTTP
- Inicio/fin de tareas Celery
- Queries a la base de datos
- Llamadas a APIs externas
- Eventos personalizados del negocio

## Uso del APM en el código

### Capturar excepciones manualmente

```python
from app.apm import capture_exception

try:
    # Código que puede fallar
    risky_operation()
except Exception as e:
    capture_exception(e, extra={
        "context": "additional_info",
        "user_id": user_id
    })
    raise
```

### Agregar breadcrumbs personalizados

```python
from app.apm import add_breadcrumb

add_breadcrumb(
    message="Iniciando análisis de partida",
    category="analysis",
    level="info",
    data={
        "game_id": game_id,
        "moves": move_count
    }
)
```

### Establecer contexto de usuario

```python
from app.apm import set_user_context

set_user_context(
    username=player_username,
    user_id=player_id
)
```

### Medir rendimiento de funciones específicas

```python
from app.apm import measure_performance

@measure_performance("analysis.stockfish", "Análisis con Stockfish")
def analyze_with_stockfish(pgn_text: str):
    # Código de análisis
    pass
```

## Dashboard de Sentry

### Vistas principales

1. **Issues**: Lista de errores agrupados por similitud
2. **Performance**: Métricas de rendimiento y transacciones lentas
3. **Discover**: Consultas personalizadas sobre eventos
4. **Dashboards**: Paneles personalizados con métricas clave

### Alertas recomendadas

Configurar alertas para:

- Error rate > 5% en cualquier endpoint
- Tiempo de respuesta P95 > 1 segundo
- Tareas Celery fallidas > 10 por hora
- Nuevos tipos de errores no vistos antes
- Degradación del rendimiento > 20%

## Mejores prácticas

### 1. Sampling estratégico

- Usar sampling bajo en producción para reducir costos
- Aumentar sampling temporalmente para debugging
- Priorizar transacciones críticas con sampling más alto

### 2. Información sensible

- No enviar contraseñas, tokens o información personal
- Usar `before_send` para filtrar datos sensibles
- Revisar la configuración de privacidad en Sentry

### 3. Contexto útil

- Agregar tags para categorizar eventos
- Incluir contexto relevante del negocio
- Usar breadcrumbs para trazar el flujo de ejecución

### 4. Monitoreo proactivo

- Revisar regularmente el dashboard
- Configurar alertas para problemas críticos
- Analizar tendencias semanalmente

## Resolución de problemas

### APM no captura eventos

1. Verificar que `SENTRY_ENABLED=true`
2. Confirmar que el DSN es correcto
3. Revisar logs para errores de inicialización
4. Verificar conectividad de red a Sentry

### Demasiados eventos

1. Reducir `SENTRY_TRACES_SAMPLE_RATE`
2. Filtrar rutas no importantes (health checks, etc.)
3. Usar `before_send_transaction` para filtrar

### Información faltante

1. Aumentar `SENTRY_MAX_BREADCRUMBS`
2. Agregar más contexto manualmente
3. Verificar integraciones activas

## Costos y límites

### Plan gratuito de Sentry

- 5,000 errores/mes
- 10,000 transacciones de rendimiento/mes
- 10 GB de attachments
- Retención de 30 días

### Optimización de costos

1. Usar sampling inteligente
2. Filtrar eventos no importantes
3. Agrupar errores similares
4. Limpiar datos antiguos regularmente

## Integración con otras herramientas

### Prometheus + Grafana

El APM de Sentry complementa las métricas de Prometheus:

- Prometheus: Métricas de infraestructura y sistema
- Sentry: Errores y rendimiento de aplicación

### Logging

Los logs siguen siendo importantes:

- Logs: Información detallada para debugging
- Sentry: Errores y métricas agregadas

### CI/CD

Integrar Sentry en el pipeline:

```bash
# Notificar a Sentry sobre un nuevo release
sentry-cli releases new $VERSION
sentry-cli releases set-commits $VERSION --auto
sentry-cli releases finalize $VERSION
```

## Conclusión

El APM con Sentry proporciona visibilidad completa sobre el comportamiento de la aplicación en producción. Con la configuración adecuada, permite identificar y resolver problemas antes de que afecten a los usuarios.

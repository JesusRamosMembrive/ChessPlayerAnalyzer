    Guía de Desarrollo - ChessPlayerAnalyzer

    Audiencia: Desarrolladores, Contributors Última actualización: 2025-09-13 Estado: Completo

    Guía completa de desarrollo basada en el flujo real de trabajo actual, incluyendo setup local, debugging y workflow con Docker profiles.

    <¯ Overview del Stack

    Backend: - FastAPI - API REST con validación Pydantic - Celery - Procesamiento asíncrono con Redis broker - PostgreSQL - Base de datos principal - PyTorch - ML models en worker dedicado - Stockfish - Engine de análisis de chess - Docker Compose - Orquestación con profiles

    Frontend: - Next.js 15 - Framework React con App Router - React 19 - UI library con hooks modernos - TypeScript - Type safety end-to-end - Tailwind CSS + Radix UI - Styling y components - TanStack Query - Data fetching y caching - Zod - Runtime validation

    = Setup de Desarrollo

    Prerrequisitos

    # Herramientas necesarias
- Docker Desktop
- Git
- Node.js 18+ (para frontend)
- Python 3.12+ (para testing local)
- Stockfish (opcional, para análisis local)

    1. Clone y Setup Inicial

    # Clone del repositorio
git clone <repository-url>
cd ChessPlayerAnalyzer

# Verificar estructura
ls -la
# Debe mostrar: app/, "UI React/", docker-compose.yml, etc.

    2. Backend Setup

    # Construir imágenes
docker-compose build

# Verificar servicios disponibles
docker-compose config --services
# Output: jaeger, postgres, redis, migrate, backend, celery, celery-torch

    3. Frontend Setup

    cd "UI React/ChessPlayerAnalyzerReact"

# Instalar dependencias
npm install
# o si usas pnpm (recomendado):
pnpm install

# Desarrollo local
npm run dev
# Frontend disponible en: http://localhost:3000

    =' Comandos de Desarrollo

    Docker Compose Profiles

    Desarrollo estándar (sin ML): 

    # Backend + Celery + DB + Jaeger
docker-compose --profile dev up

# Con rebuild
docker-compose --profile dev up --build

# En background
docker-compose --profile dev up -d

    Desarrollo con ML/PyTorch: 

    # Backend + Celery + Torch worker + DB
docker-compose --profile dev --profile ml up

# Solo ML worker (si backend ya está up)
docker-compose --profile ml up celery-torch

    Desarrollo completo: 

    # Todos los servicios
docker-compose --profile dev --profile ml up

# Con logs de solo algunos servicios
docker-compose --profile dev --profile ml up backend celery-torch

    Comandos Útiles

    Reset completo (tu flujo actual): 

    # Parar y limpiar
docker-compose down -v

# Rebuild y start
docker-compose --profile dev --profile ml build
docker-compose --profile dev --profile ml up

    Logs y debugging: 

    # Logs de servicio específico
docker-compose logs -f backend
docker-compose logs -f celery
docker-compose logs -f celery-torch

# Logs con timestamps
docker-compose logs -f -t backend

# Últimas 100 líneas
docker-compose logs --tail=100 backend

    Database operations: 

    # Conectar a PostgreSQL
docker-compose exec postgres psql -U chess -d chessdb

# Migrations (automáticas en container)
docker-compose exec backend alembic upgrade head

# Reset DB (elimina volumen)
docker-compose down -v
docker-compose --profile dev up migrate backend

    Exec en containers: 

    # Shell en backend
docker-compose exec backend bash

# Python shell con app context
docker-compose exec backend python -c "from app.models import *; from app.database import engine"

# Celery inspect
docker-compose exec celery celery -A app.celery_app inspect active
docker-compose exec celery celery -A app.celery_app inspect stats

    = Debugging y Testing Local

    Script de Testing Local

    El proyecto incluye test/run_local_analysis.py para testing rápido sin Docker:

    # Testing local sin Docker (tu enfoque actual)
cd test/

# Analizar archivo JSON local
python run_local_analysis.py \
    --input data/sample_games.json \
    --username "hikaru" \
    --verbose \
    --engine-path "/usr/games/stockfish"

# Procesar directorio completo
python run_local_analysis.py \
    --input-dir data/ \
    --pattern "*.json" \
    --out-dir results/ \
    --csv

# Sin engine (para debugging rápido)
python run_local_analysis.py \
    --input data/games.json \
    --engine-disable \
    --summary-only

    Ventajas del Script Local:

    • Rápido: No requiere Docker rebuild
    • Debugging directo: Output inmediato y stack traces claros
    • Flexible: Diferentes engines, configuraciones
    • CSV export: Para análisis de datos

    Debugging Strategies

    1. API Debugging: 

    # Verificar endpoints activos
curl http://localhost:8000/api/v1/health

# Test análisis de jugador
curl -X POST http://localhost:8000/api/v1/players/hikaru \
  -H "Content-Type: application/json"

# Check task status
curl http://localhost:8000/api/v1/tasks/{task_id}

    2. Database Debugging: 

    -- Conectar y inspeccionar
\c chessdb
\dt
SELECT * FROM player LIMIT 5;
SELECT COUNT(*) FROM game;

    3. Celery Debugging: 

    # Monitor tasks en tiempo real
docker-compose exec celery celery -A app.celery_app events

# Purge todas las tasks
docker-compose exec celery celery -A app.celery_app purge

# Worker stats
docker-compose exec celery celery -A app.celery_app inspect stats
docker-compose exec celery-torch celery -A app.celery_app inspect stats

    4. ML Debugging: 

    # Test PyTorch worker
docker-compose exec celery-torch python -c "
from app.ml_tasks import infer_model
import random
vector = [random.random() for _ in range(128)]
result = infer_model.delay(vector)
print(result.get())
"

# Check model loading
docker-compose exec celery-torch python -c "
from app.ml.inference import get_model
model = get_model()
print(f'Model loaded: {model}')
"

    = Development Workflow

    Tu Flujo Actual (Optimizado)

    Desarrollo iterativo: 

    # 1. Parar servicios
docker-compose down

# 2. Cambios en código (app/ o frontend)
# ... edit files ...

# 3. Restart rápido (sin -v si no cambió DB schema)
docker-compose --profile dev up --build backend celery

# 4. Test con frontend
cd "UI React/ChessPlayerAnalyzerReact"
npm run dev # Si no está corriendo ya

# 5. Test específico con script local
python test/run_local_analysis.py --input test_data.json --engine-disable

    Para cambios de ML: 

    # Rebuild solo torch worker
docker-compose build celery-torch
docker-compose --profile ml up celery-torch

    Para cambios de DB schema: 

    # Reset completo necesario
docker-compose down -v  # Elimina volúmenes
docker-compose --profile dev up  # Recrear DB

    Workflow Optimizado Recomendado

    Desarrollo rápido sin Docker: 

    # 1. Setup inicial con Docker (una vez)
docker-compose --profile dev up postgres redis -d

# 2. Backend local con hot reload
export DATABASE_URL="postgresql+psycopg://chess:chess@localhost:5432/chessdb"
export REDIS_URL="redis://localhost:6379/0"
cd app/
uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 3. Celery worker local
celery -A app.celery_app worker --loglevel=info

# 4. Frontend local
cd "UI React/ChessPlayerAnalyzerReact"
npm run dev

    =Ê Monitoring y Observabilidad

    Jaeger Tracing

    URL: http://localhost:16686

    Uso durante desarrollo: - Ver request flows completos - Debug performance bottlenecks - Trace Celery task execution - Correlacionar errores entre servicios

    Logs Estructurados

    # Backend logs con contexto
docker-compose logs backend | grep -E "(ERROR|WARN|task_id)"

# Celery task tracking
docker-compose logs celery | grep -E "(task|error|success)"

# Filter por usuario
docker-compose logs backend | grep "username.*hikaru"

    Database Monitoring

    -- Queries útiles para debugging
SELECT
    username,
    created_at,
    updated_at,
    analysis_status
FROM player
ORDER BY updated_at DESC LIMIT 10;

-- Task execution times
SELECT
    username,
    COUNT(*) as games_count,
    AVG(extract(epoch from (end_time - created_at))) as avg_duration_seconds
FROM game
WHERE end_time IS NOT NULL
GROUP BY username;

    =¨ Troubleshooting Común

    Problemas de Docker

    # Port conflicts
docker-compose ps
# Si hay conflictos, parar otros servicios en puertos 8000, 5432, 6379

# Disk space
docker system prune -a

# Network issues
docker-compose down
docker network prune
docker-compose up

    Problemas de Base de Datos

    # Reset DB si hay corrupción
docker-compose down -v
docker volume ls | grep postgres
docker volume rm <volume_name>
docker-compose --profile dev up

    Problemas de Frontend

    # Clear Next.js cache
cd "UI React/ChessPlayerAnalyzerReact"
rm -rf .next/
npm run dev

# Dependency issues
rm -rf node_modules/ package-lock.json
npm install

    Problemas de ML Worker

    # Check PyTorch installation
docker-compose exec celery-torch python -c "import torch; print(torch.__version__)"

# Model loading issues
docker-compose exec celery-torch ls -la /app/model_store/

# CUDA/CPU detection
docker-compose exec celery-torch python -c "import torch; print(f'CUDA: {torch.cuda.is_available()}')"
